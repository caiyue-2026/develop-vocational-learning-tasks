# 使用说明

## 准备与安装

从仓库首页下载纯技能ZIP，解压后确认技能目录同时包含 `SKILL.md`、`references`、`assets`、`scripts` 和 `agents`。不要只复制单个提示词文件，以免缺少理论编写和质量审查规则。

在支持技能包导入的客户端中使用其导入功能；支持项目技能目录的工具按其文档放置完整文件夹。尚未提供适用于所有客户端的一条安装命令。完成后尝试通过技能名称或 `$develop-vocational-learning-tasks` 调用，并检查环境是否读取了技能规则。

不能识别技能目录的普通聊天环境，可提供SKILL及其引用资料辅助执行，但这属于手动提供上下文，不能据此宣称已经安装技能。

## 输入信息

| 信息 | 建议内容 |
|---|---|
| 专业与层次 | 如高职汽车检测与维修技术 |
| 课程与任务 | 明确本次开发的范围和工作对象 |
| 学时与基础 | 学生已有知识技能、课堂与实操时间 |
| 工作条件 | 设备、工具、材料、资料和可实施方式 |
| 成果要求 | 实物、报告、图样、程序、服务记录等 |
| 技术依据 | 课程标准、操作手册、图纸、参数及版本 |
| 输出要求 | 学生稿/教师稿、Word或其他格式、模板和作者 |

资料充分时可直接开发；缺少资料时先说明假设与待核事项。无需编造企业、访谈或真实订单来使情境显得真实。

## 用法一 从零起步

```text
请使用职业教育学习任务开发技能，为中职某专业的某课程设计一个学习任务。
目前只有课程名称，拟用8学时，学生为二年级。
请先建立合理的任务范围与学习目标，列出教学假设和必要资料缺口，再给出完整初稿。
任务需在校内教学条件下实施，不得把假设参数写成已核实标准。
```

优先补齐会影响工作对象、操作条件和验收结论的资料，再完善一般表述。

## 用法二 依据现有材料开发

```text
请使用 $develop-vocational-learning-tasks，依据附件课程标准与技术资料开发学习任务。
保留有教学价值的工作对象、原理与图样对应，在十部分结构中重新组织。
获取信息、制定计划、任务实施、检查交付主要通过引导问题展开；问题包含明确活动与记录形式。
最后系统撰写相关知识与技术资料，解释概念、原理、方法、例题和条件。
学生稿与教师参考稿分别输出，技术资料缺口和教学模拟数据如实标明。
```

公开仓库中的学习领域9即为这种材料改编方式的成果示例。请阅读示例导读和来源说明，不把所有历史参数直接用于当前设备。

## 用法三 修改或审查已有稿件

```text
请使用职业教育学习任务开发技能审查附件任务稿。
检查十部分体例、四环节引导问题、目标与评价对应、学生操作证据及理论完整性。
先识别影响学生完成任务的缺口，再在现有基础上修改，保留已有有效内容。
不擅自补造图纸、实测数据、厂家技术结论和原始缺页内容。
```

如果用户只要诊断，输出诊断及具体修改建议；只有要求改稿时才生成修订成果。

## 生成后的检查

1. 学习情境、目标和要求是否能让学生知道要做什么。
2. 每个中间环节是否有推动实际工作的问题。
3. 计划中是否存在有意义的选择与理由。
4. 操作活动、个人记录、检查方法和交付成果是否充分。
5. 理论是否解释了关键判断，且能支持前文问题。
6. 技术参数、图样、版本、单位及引用是否准确且适用。
7. 评分是否有可观察标准，项目分值是否合计正确。
8. Word标题样式、图表、填写空间及分页是否可用。

## 运行结构校核

可将开发记录保存为JSON，字段参考技能内 `assets/design-record-template.json`。该模板含有占位文字，需替换为实际内容才能通过校核。

在技能目录执行：

```bash
python scripts/check_design.py task-design.json
```

退出码0表示结构检查无错误，1表示存在结构或内容占位问题，2表示输入文件无法读取或解析。警告需教师判断；脚本通过不代表专业内容已经审核。

## 格式及作者

本技能当前默认A4、黑色文字，标题和正文采用配套格式要求；默认Word作者及备注为蔡跃。公共使用者可在本次任务中明确指定自己的文档作者、备注和学校模板，本次明确要求优先。公开示例保持作者提供的文件原样，不重排其内容。

## 常见问题

无法调用技能时，先检查是否复制了完整目录及客户端是否支持技能。无法导出Word时，检查文档工具、渲染器和字体；暂时只能输出文本时应如实说明。理论过短时，要求补充概念关系、原理解释、方法条件和完整例题，避免仅增加无关篇幅。问题过于简单时，增加分析材料、方案判断依据和迁移条件，不能只替换动词。
