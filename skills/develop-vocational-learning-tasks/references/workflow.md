# 开发流程与体例

## 起步方式

识别专业和层次、课程和任务、学时、学生基础、设备场地、已有资料、预期成果及用途。用户已提供的信息直接复用。只有名称时，给出合理模拟条件和资料缺口；已有课程标准时提取能力及目标；已有普通教材时重新建立学习任务；已有活页稿时诊断和修订。

整本教材先拟任务清单、目标覆盖和学时安排，随后逐任务开发。六案例提供任务开发方法，不能代替各专业完整的课程体系。

## 十部分要求

### 一 学习情境

用完整段落说明委托背景、岗位角色、具体工作对象、真实需求和限制。注明真实或教学模拟资料性质，减少无关故事情节。

### 二 学习目标

目标采用可观察行为，尽量包含条件、标准和工作结果。复杂任务可先设 4—8 项并按需调整。例如：依据给定装配图和工艺要求，选用量具完成规定部位检测，填写完整记录并判定是否合格。沟通协作和职业态度嵌入具体责任。

### 三 任务要求

写清输入资料、完成内容、交付形式、质量依据、期限和提交方式。区分岗位交付期限和课堂学时；涉及养护、观察和等待时，安排跨时段活动或使用标明性质及来源的教学数据。任务条件应足以支持开展活动。

### 四 任务分工

按实际设置角色、职责、个人成果和协作事项。个体任务按本人开展；小组任务安排轮岗或个人核验，保证每人有学习与操作机会。表格不虚填姓名和学号。

### 五 获取信息

通过引导问题组织任务解读、工作对象识别、原理规范查阅、原始资料核对、资源及风险识别。允许学生发现缺失和矛盾并提出核实办法。设置图纸批注、信息提取表、资料核对表及解释区。

### 六 制定计划

通过引导问题完成方案构思、比较、选择与理由说明，形成步骤、工具材料、分工、进度、关键参数和质量控制安排。方案比较采用适用性、质量、成本、效率、资源等具体维度。仅有一种合理流程时比较工具、参数或次序，不强造无意义方案。

### 七 任务实施

按专业工作步骤组织问题，要求学生实际计算、绘制、操作、编制、试验或服务。提供必需说明和记录表，保留判断空间，写明必须遵守的要求。设置异常记录与处理活动，反映计划和实施的差异。实操采用已核实的设备说明和现场要求，安排适当教师指导。

### 八 检查交付

通过问题组织检查方法选择、数据获取、标准判定、原因分析、整改复检、资料整理与交付。验收表写明项目、方法、条件、合格要求、记录与结论。图纸文档类采用审查、互核和解释一致性检查；服务类采用服务记录和交付确认；不一律套实体尺寸表。

### 九 评价反思

组织自评、适用的互评和教师评价。围绕目标与证据分析哪些判断依据不足、哪些操作需改进、条件变化时如何调整，避免只问收获体会。明确技术验收与学习评价的关系，防止重复计分。

### 十 相关知识与技术资料

单独形成完整的理论正文，按概念原理和方法之间的关系组织，不照抄四环节名称。包括必要概念、原理、公式、方法、例题、规范和常见错误。技术资料配合解释使用。详见理论编写规则。

## 内部对应关系

| 对象 | 编号 | 记录内容 |
|---|---|---|
| 学习目标 | O1 | 行为、条件、标准及成果 |
| 引导问题 | Q01 | 环节、层级、目标、资料、知识小节、活动及证据 |
| 理论小节 | K1.1 | 名称、完整正文、支持目标和来源 |
| 学生成果 | E1 | 形式、完成条件及质量依据 |
| 评价项目 | A1 | 标准、证据、主体和分值 |
| 技术来源 | S1 | 名称、机构、版本、位置、状态及适用条件 |

学生版可只展示问题和知识查阅编号，完整对应关系保留在教师参考稿或开发记录中。
